# 电脑使用统计（UseStats）

Windows 电脑使用时长统计：一个常驻托盘的**记录程序**负责采集每天各应用的**前台 / 后台**使用情况，一个**查看器**负责 Looseleaf 手绘风界面的统计展示与设置（鼠尾草绿桌面上摊一张横线本纸：纸面 + 蓝格线 + 红页边线、卡片为奶油纸片配墨线勾边与不对称手绘圆角、暖棕硬阴影、中文手写体 + 数字等宽；总览一屏、图表 2×2、设置双列的信息密度不变；界面按显式字阶排版、已做 WCAG AA 无障碍处理，颜色用途有固定语义规则，详见文件表 `stats.html` 一行与「颜色语义」一节）。两个程序放在同一目录、共用同一份数据。

| 程序 | 职责 |
|---|---|
| `UseStatsRecorder.exe` | **记录程序**：托盘常驻、每秒采样前台应用、每 10 秒枚举后台进程、每 60 秒落盘；开机自启指向它；负责 settings.json 的热加载与旧数据清理；另带 WiFi 辅助（未连 WLAN 时刷新可用网络列表并自动连接已保存网络，见「WiFi 辅助」一节）。相对轻量（不含 WebView2）。 |
| `UseStats.exe` | **查看器（主程序）**：双击打开手绘风界面窗口（总览 / 图表 / 设置三页）；纯查看器——不采集、不占用采集互斥量、不注册任何托盘图标；点窗口红 X 只把窗口隐藏收起（进程不退出），唤出与真正退出都走记录程序那唯一的托盘图标（单击唤出、菜单「关闭查看器」真退出）；每次启动还会顺手校准开机自启指向并在记录程序没运行时把它拉起（见「开机自启由谁负责」）。 |

> **从旧单 exe 版迁移**：先在任务管理器里结束正在运行的旧版 `UseStats.exe` 进程（很重要：旧版还在运行时，它的单实例逻辑会拦截新程序的启动），再把本目录的两个新 exe 放进原程序目录（数据 `usage-*.json` 就在那里，不要换目录），旧的 `UseStats.exe` 会被同名查看器直接覆盖。之后双击 `UseStatsRecorder.exe` 启动记录；它首次启动时会把注册表自启从旧 `UseStats.exe` 自动刷新为指向自己的路径，无需手动处理。`stats_view.html` / `stats_data.js` 是更早版本留下的文件，可删。

## 使用方法

1. **启动记录**：双击 `UseStatsRecorder.exe`。它没有窗口，只在系统托盘出现黄色时钟图标，表示正在记录；启动时会自动把查看器打开一次。记录程序是单实例（互斥量沿用 `Local\UseStats_SingleInstance`）：重复双击不会多开，只会让已有实例把查看器调出来。**全系统只有这一个托盘图标**（查看器不注册图标），它就是两个程序共同的入口与出口。
2. **看统计**：**单击托盘图标**即可打开/唤出统计界面（不用双击）；或双击 `UseStats.exe`；或托盘右键 →「打开统计界面」。查看器也是单实例，重复双击、托盘单击都只是把已有窗口唤出（窗口被红 X 收起隐藏时同样能唤出，并按最新数据刷新）。窗口分三页（顶部导航切换，不刷新）：
   - **总览**：今日 / 近 7 天 / 近 30 天三档切换、总时长等数字块、分布图、Top 10 排行，平均时长卡置于详情卡之后（扫读顺序固定为：用了多久 → 主要用在哪些应用 → 与其他日期相比如何）；顶部条显示「今日使用最多」的应用（数据来自记录器最新落盘的当日文件，记录器每 60 秒落盘一次，故最多有约 1 分钟延迟）。
   - **图表**：近 30 天每日总时长趋势（柱 + 7 日移动平均折线，SVG 手绘）、时段分布（近 30 天 hourlyFg 按小时合计）、星期规律（周一至周日日均）、应用占比（Top 6 环图 + 图例，其余归「其他」）。
   - **设置**：见下节。改动即时保存并有「已保存」反馈。
   - **悬停摘要**：鼠标悬停在托盘图标上会显示今日摘要，例如「今日 5小时23分｜Chrome 1小时52分 · VS Code 1小时10分 · 微信 45分」——今日前台总时长 + 用时最长的 3 个应用，每 60 秒刷新一次；当天还没有记录时显示「今日暂无记录」。
   - **配色方案**：4 套主题（键名沿用 classic/soft/dark/red）——「账册蓝」（默认）、「晴蓝」、「墨黑」、「朱红」。**只在设置页切换**（总览页不设换肤入口），点色块按钮即时生效，保存在 settings.json 里（localStorage 只是降级缓存）。
3. 记录程序托盘右键菜单：「打开统计界面」（默认项）/「关闭查看器」/「打开数据文件夹」/「开机自启」（默认开，见下）/「退出记录程序」（退出前先落盘）。其中「关闭查看器」只在查看器运行中（含被红 X 收起的隐藏状态）时可用，灰掉表示查看器本来就没开。
4. 两个程序各自的退出路径：点查看器窗口的红 X **不会**退出查看器，只是把窗口隐藏收起（窗口隐藏、进程与 WebView2 保持存活；隐藏前查看器会顺手确认记录程序在跑、不在就拉起它，保证托盘图标这个入口永远在场），随时单击托盘图标或再双击 exe 唤出；真正退出查看器要用记录程序托盘菜单的「关闭查看器」。「退出记录程序」只停记录，**查看器窗口开着就继续开着**，两者互不连带；反过来，关查看器也不影响记录。

## 设置（settings.json）

设置保存在程序目录的 `settings.json`，**查看器写、记录器读**。在查看器的设置页修改后即时保存（原子替换写入，不会读到半截）；记录器每 60 秒检查一次文件修改时间，变了就热加载，**不用重启记录程序**。文件缺失或损坏时两边都用默认值，不崩。

| 字段 | 含义 | 可选值（默认） | 生效方式 |
|---|---|---|---|
| `idleSeconds` | 空闲判定秒数：无键鼠操作超过此时长，前台时间转记为空闲 | 60 / 120 / 180 / 300 / 600（默认 180） | 记录器热加载，改完一分钟内生效 |
| `backgroundStats` | 后台统计开关：关掉后不再枚举进程，`bgSeconds`/`cpuSeconds` 停止增长 | true / false（默认 true） | 记录器热加载 |
| `retentionDays` | 数据保留天数：更旧的 `usage-*.json` 自动删除 | 0=永久 / 90 / 180 / 365（默认 0） | 记录器在启动、跨天、以及该值被改动时各清理一次 |
| `theme` | 界面主题 | classic / soft / dark / red（默认 classic） | 查看器打开时读入；页面切换时写回 |
| `autoStart` | 开机自启的期望状态**镜像** | true / false（默认 true） | 见下：真理在注册表 |
| `wifiAssist` | WiFi 辅助总开关（扫描保鲜） | true / false（默认 true） | 记录器热加载 |
| `wifiAutoConnect` | 自动连接已保存网络（依赖 `wifiAssist` 开启） | true / false（默认 true） | 记录器热加载 |

### WiFi 辅助（记录程序）

解决一类真机毛病：电脑没连上 WLAN 时，系统的可用网络列表会像冻住一样不刷新——明明附近有网，点开状态栏却搜不到，每次都要手动去连。记录程序内置了一个低频状态机（每 15 秒检查一次）代劳：

- **扫描保鲜**（`wifiAssist`，默认开）：未连接 WLAN 时，每约 45 秒对无线网卡调用一次 Native WiFi API 的 `WlanScan`，强制系统刷新可用网络列表；下次点开状态栏，列表就是新鲜的。已连接时不扫描。
- **自动连接已保存网络**（`wifiAutoConnect`，默认开，需 `wifiAssist` 同时开启）：未连接持续超过 20 秒后，从「当前可用网络 ∩ 本机已保存过配置文件的网络」里挑信号最强的一个，用保存的配置文件发起 `WlanConnect`；两次尝试至少间隔 60 秒，防止反复重连。**只连已保存过的网络，绝不连接陌生或没保存过的开放网络。**
- 无线网卡不存在（纯有线机）时功能静默待命；`wlanapi.dll` 是运行时动态加载的（不进 exe 导入表），DLL 缺失或 WLAN 服务（WlanSvc）被停用/禁用时，功能记一行日志后整体关停——**不影响记录主业，更不会让记录程序崩溃**。若网卡被硬件开关 / 飞行模式 / 驱动层面关掉，`WlanScan` 也无能为力，这种情况日志里会留下接口状态或错误码。
- 全部动作与状态变化写 `stats_debug.log`，前缀 `wifi:`，例如：`wifi: assist ready`、`wifi: disconnected, scan requested`、`wifi: auto-connect "<SSID>" result=0`（result 是 WlanConnect 的返回码，0 = 请求已受理，实际连上后另有一行）、`wifi: connected "<SSID>"`、`wifi: no saved network in range`、`wifi: disabled (...)`。
- 两个开关在查看器的设置页「网络辅助」一组里，改动经 settings.json 热加载到记录程序，一分钟内生效。

### 开机自启由谁负责（一致性方案）

自启的**真理在注册表**，不在 settings.json：

- 实际开关是 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `UseStats` 值，内容指向**记录器** `UseStatsRecorder.exe` 的完整路径；用户偏好另存于 `HKCU\Software\UseStats` 的 DWORD `AutoStart`（不存在=从未设置，1=开，0=关）——分开存是为了「首次默认开启，但手动关过必须记住」。
- 记录器与查看器共用同一份 `autostart.cpp` 实现：记录器每次启动按偏好校准 Run（从未设置→默认开启；偏好开→路径缺失/过期就刷新为记录器当前路径；偏好关→确保 Run 不存在）。
- **Run 的目标路径只有一个决定点**：`autostart.cpp` 的 `AutoStartRecorderPath(exeDir)`，永远是同目录的 `UseStatsRecorder.exe`。记录器启动校准、记录器托盘开关、查看器设置保存、查看器启动自愈四条路径都经它取目标，任何代码都不许把查看器（`UseStats.exe`）写进 Run。每次读写 Run，日志都会把实际路径落盘（`autostart: Run write target="..."` / `autostart: Run stale target="..."`)，指向对不对看日志即可，不用猜。
- 查看器设置页（或记录器托盘菜单）改自启开关时，**当场**经同一模块把 Run 值与偏好一起落注册表，即时生效，不依赖记录器是否在运行；同时把期望状态镜像写进 settings.json 的 `autoStart` 字段。记录器热加载**不**看这个镜像字段，不会覆盖用户在别处刚改的注册表状态。
- **查看器每次启动自愈**：按同一偏好规则把 Run 校准到记录器路径（若 Run 原先指着查看器自己，日志点名 `autostart(viewer): Run pointed at viewer; fixed to recorder`)，并顺手探一次记录程序的采集互斥量——没在运行就把同目录记录器拉起来（`viewer: recorder not running; launched ...`）。所以即使自启项曾经指错，打开任一程序一次即可恢复，之后开机自动记录。
- 查看器设置页打开时显示的自启状态是**现读注册表**得到的，不是镜像，所以永远准。

### 开机后没有记录？

先打开程序目录的 `stats_debug.log`，看开机时间附近有没有 `recorder: start` 这一行：

- **没有** → 记录程序开机时根本没被启动，即自启项没生效（Run 缺失、指向旧目录、或曾被指到查看器）。本版起打开任一程序一次即可自动修复：查看器启动时会把 Run 刷新到记录器（日志 `autostart(viewer): Run ...` + `autostart: Run write target="..."`，路径应为当前目录的 `UseStatsRecorder.exe`），并当场把记录程序拉起开始记录；修好后下次开机应能自动记录，日志里应出现开机时间附近的 `recorder: start`。
- **有 `recorder: start` 却没数据** → 自启没问题，往下看当天的 `usage-YYYY-MM-DD.json` 是否在增长、日志里有没有落盘或热加载异常，再反馈。
- 注意两个 exe 必须放在**同一目录**：自愈与拉起都以「同目录的记录程序」为准，目录里没有 `UseStatsRecorder.exe` 时日志会写 `viewer: recorder exe MISSING next to viewer`。

## 程序目录里的文件

| 文件 | 说明 |
|---|---|
| `usage-YYYY-MM-DD.json` | 每天的原始数据（记录器每 60 秒、退出时、关机前更新） |
| `settings.json` | 共享设置（见上节） |
| `stats_debug.log` | 诊断日志：托盘注册（`tray: NIM_ADD ok`）、自启（`autostart:`）、设置热加载（`settings: hot-loaded`）、WebView2 加载链路都写在这里，排障时发回这个文件 |
| `WebView2Loader.dll` | 首次打开查看器时从 exe 内释放，WebView2 的加载器（只有查看器需要） |
| `wv2data/` | WebView2 的浏览器数据目录（缓存等），可删 |

> 为什么数据放在 exe 旁边而不是 %LOCALAPPDATA%：延续已真机验证的行为，用户已有的记录文件就在 exe 目录；且整个文件夹可直接搬移备份（搬走后记录器下次启动会自动把自启路径刷新为新位置）。若 exe 被放在只读目录（如 Program Files），数据将无法写入，请勿放那里。

## 托盘图标没出现在右下角可见区？

记录程序保证图标**注册成功**（注册结果会写进 `stats_debug.log`，出现 `tray: NIM_ADD ok` 即成功；任务栏/explorer 重启后程序也会自动重新注册）。但图标默认是**折叠**在 `^`（显示隐藏的图标）面板里的，常显与否是 Windows 的用户设置，程序无法强制。把它钉到可见区：

- **Windows 11**：点任务栏右下角 `^` 打开溢出面板，把黄色时钟图标**直接拖到**任务栏右下角的可见区即可；或 设置 → 个性化 → 任务栏 → 「其他系统托盘图标」，把 UseStatsRecorder 的开关打开。
- **Windows 10**：设置 → 个性化 → 任务栏 → 通知区域 → 「选择哪些图标显示在任务栏上」，把 UseStatsRecorder 的开关打开。

## 数据口径

| 字段 | 含义 |
|---|---|
| `fgSeconds` 前台秒 | 记录器每 1 秒采样当前前台窗口所属进程；该秒记给此应用，并记入其 `hourlyFg[小时]` 格。 |
| 空闲 | 键鼠无操作达到**空闲判定阈值（settings.json 的 `idleSeconds`，默认 180 秒）**后的秒数不计入任何应用，记入当天顶层 `idleSeconds`。锁屏（LogonUI.exe / LockApp.exe）、无前台窗口、取不到进程路径时同样归入 idle。 |
| `bgSeconds` 后台秒 | 每 10 秒枚举一次进程，每个存活进程 +10 秒（`backgroundStats` 关闭时停记）。它是**存活时长，包含该应用的前台时间**；排行榜里的「后台（仅运行未在前台）」= bgSeconds − fgSeconds。记录程序自身、System/Idle、锁屏类伪应用不计入。 |
| `cpuSeconds` CPU 秒 | 同在 10 秒采样时用 `GetProcessTimes` 取增量。后台秒高但 CPU 秒≈0 是「开着没用」，CPU 秒高才是真在后台运行。 |
| 应用名 | 优先读 exe 版本信息的 `FileDescription`（如 `chrome.exe` → Google Chrome），失败回退为文件名去后缀。 |
| explorer.exe | 按正常应用计入（资源管理器是真实使用；单击桌面空白处时前台同属 explorer，一并计入）。 |

同一天重启记录程序会读回已有 json 续记，不丢数据；跨天自动切换到新日期文件。

## 统计口径（总览与图表）

- **总时长**：所选时间段内所有应用 `fgSeconds` 之和（前台口径）。
- **日均**：最近 **7 个有数据日子**的日总时长平均；数据不足 7 天时按实际天数，标签如实写「近 3 天日均」。
- **周均**：最近 **4 个有数据的自然周**（周一至周日）的周总时长平均，不足按实际周数（含本周的未完整数据）。
- **月均**：最近 **3 个有数据的自然月**的月总时长平均，不足按实际月数（含本月的未完整数据）。
- 没有记录的日子（记录程序未运行）不产生数据文件，也不计入任何平均的分母。
- **排行榜**：所选时间段内按应用聚合，**按前台秒降序**取 Top 10；条形长度按「前台 + 仅后台运行」总时长缩放，深色段为前台、浅色段为仅后台运行。
- **最专注时段**：所选时间段内 `hourlyFg` 合计最大的那一小时。
- **总览分布图**：今日 = 24 小时前台分布；近 7 天 = 每日总时长；近 30 天 = 按自然周（周一起）聚合的周总时长。
- **图表页**（窗口统一为以今天结尾的近 30 天，前台口径）：趋势柱 = 逐日总时长，折线 = **7 日移动平均**（trailing 含当日，不足 7 天按实际天数）；时段分布 = 窗口内全部记录日的 `hourlyFg` 按小时相加；星期规律 = 每个星期几的日均总时长，分母是该星期几在窗口内实际有记录文件的天数；应用占比 = 按路径聚合 fg 降序 Top 6 + 其余合并为「其他」，百分比以窗口总时长为分母。
- **图表覆盖与三态**：每张图表标题旁标注时间范围与覆盖（如「10/7 – 11/5 · 已记录 15 / 30 天」），图表页最底端有一行页脚口径说明（含平均口径）。渲染区分三态：有记录且 >0 = 实心柱；有记录且 =0 = 基线小刻（真零）；**没有记录文件的日子 = 虚线空槽位，绝不画成零柱**（星期图同理，未记录的星期几显示空槽）；趋势纵轴按窗口内实际峰值自适应（下限 600 秒），避免少量数据被压成贴地误读为「没用电脑」；已记录天数 <3 时趋势卡下方出现「数据积累中」提示。

聚合逻辑在 `stats.html` 的 `// ==AGG-BEGIN== ~ // ==AGG-END==` 段内（纯函数），总览口径有独立复算核对（见下文「测试」）。

## 颜色语义（界面颜色的固定用途）

界面里每种颜色只有一个固定含义，不随位置漂移（实现在 `stats.html` 的 CSS 变量与 JS `avatarColor`，四套主题同规则、只换色值）：

| 颜色 | 固定用途 | 出现位置（仅限这些） |
|---|---|---|

## 技术结构

| 文件 | 职责 |
|---|---|
| `recorder.cpp` | 记录程序入口：隐藏窗口、**全系统唯一的托盘图标**与菜单（单击打开查看器、菜单含「关闭查看器」）、1 秒定时器调度、settings 热加载、保留清理、单实例（采集互斥量）；每 15 秒驱动一次 WiFi 辅助；与查看器的沟通走注册消息 `UseStats.ViewerShow` / `UseStats.ViewerQuit` |
| `wifiassist.h/.cpp` | WiFi 辅助（记录程序专用）：wlanapi.dll 动态加载（不进导入表）+ 低频状态机——未连 WLAN 时每 ~45 秒 WlanScan 刷新可用网络列表，断开 ≥20 秒后自动连接「可用 ∩ 已保存」中信号最强者（尝试间隔 ≥60 秒）；无网卡/DLL 缺失/WlanSvc 不可用时静默降级，日志前缀 `wifi:` |
| `viewer.cpp` | 查看器入口：DPI/COM 初始化、查看器单实例（独立互斥量，第二实例改为给已有窗口发 `UseStats.ViewerShow` 注册消息唤出）、启动自愈（校准 Run 到记录器 + 记录程序没在运行则拉起）、打开统计窗口、消息循环 |
| `tracker.h/.cpp` | 采样：前台追踪、空闲判定（阈值可由 settings 设置）、进程枚举与 CPU 增量；记录当前前台应用 |
| `storage.h/.cpp` | 当天 JSON 的原子写入与读回（极简解析器，只解析本程序写出的格式） |
| `settings.h` | settings.json 的数据模型与纯逻辑（序列化/解析/白名单校验，不依赖 Win32，有单测） |
| `settings_io.h/.cpp` | settings.json 的 Win32 文件读写：原子替换保存、修改时间戳（供热加载比对） |
| `autostart.h/.cpp` | 开机自启：Run 值 + 偏好注册表的唯一实现，记录器与查看器共用；Run 目标路径由 `AutoStartRecorderPath()` 唯一决定（永远是同目录记录器），每次读写 Run 都把实际路径写进日志 |
| `applog.h/.cpp` | 诊断日志 stats_debug.log（由原 stats.cpp 抽出，两程序共用） |
| `appinfo.h/.cpp` | exe 路径 → 友好名（版本信息 FileDescription，带缓存） |
| `traytip.h` | 托盘悬停文案格式化（纯函数，今日总时长 + Top 3，有单测） |
| `stats.h/.cpp` | 查看器统计窗口：WebView2 宿主（动态加载 Loader）、数据/设置注入、设置页消息通道（settings:get/set、打开数据文件夹、复制数据目录路径 copy-text → 系统剪贴板并回执、顶部条读当日文件）、运行时缺失时的兜底提示；不注册托盘图标：WM_CLOSE 只隐藏窗口收起（隐藏前探记录程序存活、不在则拉起，防唯一托盘入口丢失），显示/唤出由记录器经注册消息 `UseStats.ViewerShow` 驱动（走 Open：唤出 + 重新导航刷新），真退出只有记录器菜单「关闭查看器」发来的 `UseStats.ViewerQuit`（DestroyWindow 绕过 WM_CLOSE） |

| `resources.rc` / `resource.h` | 查看器的内嵌资源：图标、页面、WebView2Loader.dll |
| `recorder.rc` | 记录程序的内嵌资源：仅图标 |
| `app.ico` | 黄底黑时钟扁平图标（16~256 共 7 个尺寸），由 `tools/make_icon.py` 生成 |
| `third_party/webview2/` | Microsoft.Web.WebView2 SDK **1.0.4314.35**（NuGet 官方包）精简：`include/` 头文件、`WebView2Loader.dll`（x64）、`compat/EventToken.h`（MinGW 大小写垫片） |
| `tests/` | fixture 数据、聚合口径核对、页面测试、settings 与托盘文案单测 |

**WebView2 集成为什么用动态加载**：Loader DLL 在首次运行前不存在于 exe 旁，若用导入库静态依赖，查看器首次启动就会因缺 DLL 被系统拒绝加载。因此 `stats.cpp` 把 DLL 内嵌为资源，首次打开窗口时释放到程序目录后 `LoadLibrary`，只取 `CreateCoreWebView2EnvironmentWithOptions` 与 `GetAvailableCoreWebView2BrowserVersionString` 两个入口。页面本身（Edge 的 WebView2 运行时）是 Windows 10/11 + Edge 自带的系统组件；**若检测不到运行时**，窗口会显示原生中文说明（数据仍在记录、如何安装、去哪看原始数据），不会崩溃或白屏。

**页面怎么加载（2026-11-05 白屏修复后）**：数据 JSON 与设置 JSON 直接内嵌进页面 HTML 字符串，用 `NavigateToString` 加载——不写页面文件、不用 `file://`，与程序目录路径（含中文/空格）和目录写权限无关。宿主全程监听导航完成/进程失败，并设 8 秒看门狗：任一环节卡住或失败都会切到原生兜底文字，窗口不会停在空白上。排障日志在程序目录的 `stats_debug.log`，记录运行时版本、环境/控制器创建返回码、数据文件数、导航结果与页面回传的渲染状态。

## 编译

### MinGW-w64（本项目实际使用的验证方式）

```
x86_64-w64-mingw32-windres resources.rc -O coff -o resources.o
x86_64-w64-mingw32-windres recorder.rc -O coff -o recorder_resources.o

:: 记录程序（不需要 WebView2 头文件）
x86_64-w64-mingw32-g++ -std=c++17 -Os -s -ffunction-sections -fdata-sections -Wl,--gc-sections -mwindows -municode -static ^
  -o UseStatsRecorder.exe recorder.cpp tracker.cpp storage.cpp appinfo.cpp ^
     applog.cpp settings_io.cpp autostart.cpp wifiassist.cpp mediawatch.cpp recorder_resources.o ^
  -lversion -lshell32 -ladvapi32 -lole32 -luuid

:: 查看器
x86_64-w64-mingw32-g++ -std=c++17 -Os -s -ffunction-sections -fdata-sections -Wl,--gc-sections -mwindows -municode -static ^
  -I third_party/webview2/include -I third_party/webview2/compat ^
  -o UseStats.exe viewer.cpp stats.cpp storage.cpp tracker.cpp appinfo.cpp ^
     applog.cpp settings_io.cpp autostart.cpp mediawatch.cpp resources.o ^
  -lversion -lshell32 -lole32 -lshlwapi -ladvapi32 -luuid
```

### Visual Studio

两个程序各建一个「空项目」：记录程序加入 `recorder.cpp`、`wifiassist.cpp` 与共享的 `tracker/storage/appinfo/applog/settings_io/autostart` 源文件 + `recorder.rc`；查看器加入 `viewer.cpp`、`stats.cpp` 与同样的共享源文件 + `resources.rc`（WiFi 辅助只在记录程序里，靠运行时动态加载 wlanapi.dll，无需 wlanapi 导入库）。项目属性（所有配置）：字符集 **Unicode**；运行库 **/MT**；C/C++ 命令行附加 **/utf-8**；链接器子系统 **窗口 (/SUBSYSTEM:WINDOWS)**；查看器另需 C/C++ 附加包含目录 `third_party\webview2\include`（**不要**加 `compat`）。链接依赖已由源码内 `#pragma comment(lib, ...)` 部分引入（MSVC 分支），其余（shell32/advapi32）为 VS 默认库。
